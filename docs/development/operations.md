# 运行与数据维护

仅在涉及对应操作时读取相关章节。这里描述验收要求及已知实现限制，不代表这些保护已全部由程序自动实现。

## 数据恢复与存储变更

主状态文件为 `%APPDATA%\xiaolu-desktop-pet\xiaolu-study-state.json`；本机日记目录配置为同目录的 `xiaolu-local-integrations.json`。主进程的 `loadState`、`persistState` 和 `game.ts` 的 `normalizeStudyState` 是存储入口。应用版本与状态文件的 `version` 含义不同，不能因为发新版软件就改变状态格式版本。

准备修改真实数据时：

1. 确认使用中的可执行文件、实际数据目录、文件时间和 JSON 是否可解析。比较日期集合、会话、打卡、任务、报告、外部日记、奖励和设置，而非只比较文件体积。
2. 停止会写入目标文件的共学日记实例；创建不覆盖已有文件的时间戳备份，并验证备份可读。保留原始字节，备份放在仓库外。
3. 先生成独立候选文件。按日期、记录标识、来源和时间解决冲突，保留备份之后的新增内容。不能按 JSON 字符串长度挑选“更丰富”的对象，也不能对所有数值取最大值——目标调整、撤销和合法更正可能降低数值。
4. 外部 Markdown 日记只提供标题，不是学习事实来源；同步标题不能重建或替换整天记录。缺失旧字段与明确写入零/false 必须区分。旧 YuQuiz 事实仍属于历史，不因切换 YuReader 丢弃。
5. 对候选执行当前规范化、统计及再次规范化，比较前后日期和重要字段，验证不重复累计。通过后原子替换，并重启实际使用版本，确认读入、写回和界面显示都保留恢复结果。

迁移测试使用虚构的旧格式样本，包含只有标题的日期、完整旧记录、新 YuReader 记录、零值、撤销、重复会话和跨日。数据读取失败时要保护原文件；现有 `loadState` 捕获错误后返回初始状态，存在随后写回覆盖的风险，不能把它当作已完成的自动恢复机制。

2026-09 曾观察到历史日期缺失、部分日期只剩外部日记标题，并从旧备份恢复。该现象不能单独证明是某次迁移、安装器或具体函数导致；未取得复现、调用轨迹或日志前，根因应标记为未确定。

## YuReader 联动排查

当前入口：`src/yureader.ts` 解析状态，`src/main.ts` 拉取并保存快照、消费事件和发送界面状态，`src/game.ts` 计算学习与奖励。若需要跨项目核对，读取本机 YuReader 项目的 `AGENTS.md` 与 `docs/COMPANION_API.md`；以实际响应及代码确认契约。

推荐按故障缩小检查范围：

- **后端与页面**：确认 8775 的进程归属、`/api/health`、`/api/companion/status` 的时间及 `page.study_state`。服务可达不等于网页打开，网页打开不等于正在计时。旧 YuQuiz 的 8765 拒绝连接不能解释当前 YuReader 故障。
- **时长和目标**：在真实活动期间连续采样接口，再比较小鹿保存的同一 `study_day` 快照、进度和界面。上游累计值按快照替换，不把每次轮询值相加。记录实测更新间隔，不把一次采样推断为永久刷新周期。目标修改与回写单词需要对应路径验证。
- **事件与反馈**：核对事件类型、游标推进和重复过滤；事件游标与统计量各自验证。确认实际动作和语音后才能声称反馈正常。监听函数存在或测试通过并不证明启动时已注册监听器。
- **关闭、暂停与恢复**：分别验证 ready、learning、consulting、paused、closed；检查过期快照、睡眠恢复、断线重连和手动计时切换。学科原始进度与小鹿奖励加成分开比对。
- **自动启动与位置**：冷启动必须先使后端健康，再打开或复用正确标签页。验证当前规则的触发时段、打卡计时前提、巡逻退出、返程和置顶，而不是仅检查函数存在。

优先观察用户已有活动。需要答题、背词、领奖、修改目标的测试在隔离数据环境进行；若没有隔离能力，说明该项未做写入验收。报告分别注明现场观察、隔离测试和源码检查的结论。

## 界面、声音与说明书

`scripts/create_manual_preview.mjs` 提供虚构界面数据；它用于布局和截图，不能替代 Electron 窗口或真实联动验收。检查当前窗口尺寸及 Windows 缩放下的一屏显示、长文字、分页、粒子和气泡裁切。桌面透明区的点击穿透、边缘拖动、释放鼠标及菜单关闭后的跑步状态单独检查。

语音修改核对台词映射、文件存在和实际播放。当前精简 PDF 说明书生成入口为 `scripts/create_compact_manual.py`（旧 DOCX 版生成器 `scripts/create_companion_manual.py` 仅作历史保留），长图拼接为 `scripts/stitch_manual_pages.py`；生成 PDF 后逐页渲染检查，再更新 `docs/xiaolu-study-guide.pdf` 和 README 折叠预览。说明书只用可公开素材和虚构数据，不包含个人日记或真实任务。

## 构建、安装与发布

命令以 `package.json` 为准：`pnpm build`、`pnpm typecheck`、`pnpm test`、`pnpm check`、`pnpm package:msi`。构建会替换 `dist/`；MSI 输出在 `release/`。纯文档修改不需要重建程序或跑全量测试。

当任务包含发布时：

1. 确认工作区变更与发布范围，按用户要求设置版本；保留 `appId`、数据目录名和固定 MSI `upgradeCode`，避免产生另一份安装或读到空数据。
2. 运行 `pnpm check` 和本次功能需要的运行验收。Electron 二进制缺失时检查安装脚本和依赖配置，不挪用旧安装目录冒充新构建。
3. 打包前准备真实数据备份；安装时只结束目标应用。核对 MSI 退出结果、系统登记版本、实际进程路径及安装目录 `resources/app.asar` 与构建产物的哈希。
4. 启动安装版，核对核心数据、当天进度和相关功能。进程存在只能证明已启动；安装文件哈希一致也不能证明数据完整。
5. 检查提交清单、公开截图、素材与文档，排除个人数据及私有路径。源码、标签、发布说明、MSI 与 PDF 对应同一版本；上传后核对 Release 资产及校验值。

GitHub 上传和 Release 不是每次修改的默认步骤；执行用户已经授权的发布范围即可。历史发布说明保留原貌，当前说明更新到实际交付行为。
